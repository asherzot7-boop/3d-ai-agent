# Immunolab — рабочее приложение центра (Наманган)

Цифровая модель медицинского центра Immunolab: лаборатория, клиника, вакцинация.
Одно приложение (одна HTML-страница) с разделами для руководителя и сотрудников, плюс ИИ-офис из 9 агентов.

Живая версия работает внутри Claude (claude.ai): там есть общая база данных, вход сотрудников и ИИ.
Эта папка — полная копия кода и данных, чтобы команда могла изучить, проверить и помочь исправить проблемы.

## Что внутри папки

| Путь | Что это |
|---|---|
| `app/index.html` | Готовое приложение одним файлом. Открывается в браузере, но **без Claude** база и ИИ не работают (см. ниже). |
| `app/immunolab-claude.html` | Тот же файл в виде, в котором он публикуется в Claude (без `<html><head>`). |
| `src/modules/*.html` | Исходники разделов: `model3d` (3D 1 этажа), `dashboard`, `school` (Мактаб), `problems` (форма проблем), `scanner` (сканер документов), `agents` (ИИ-офис). |
| `src/hub.html` | Оболочка: вкладки, главная, выбор «Кто вы», доступ по должностям, чек-лист проверки. |
| `src/guides.py` | Учебные пособия на 5 дней для 18 сотрудников и 2 вакансий, доступ к разделам, «Мой день в приложении». |
| `src/build.py` | Сборка: склеивает все разделы в один файл `app/`. Запуск: `python3 src/build.py` (Python 3.8+). |
| `data/guides.json` | Пособия и права доступа в виде данных. |
| `data/documents_checklist.json` | 80 документов в 10 папках: ответственный, периодичность, важность. |
| `data/catalog_vaccines.json` | Прайс вакцинации (15 позиций, утверждён 02.09.2025). |
| `tests/` | Автотесты (Playwright) и имитация Claude `mock.js`. Пути внутри указаны под нашу машину, их нужно поправить. |

## Разделы приложения

1. **Bosh sahifa (главная)**. Руководитель видит чек-лист проверки и может смотреть приложение «глазами» любого сотрудника. Сотрудник выбирает своё имя и видит «Bugun ilovada» — что делать в приложении каждый день.
2. **ИИ-офис**. 9 агентов за столами. Главный агент принимает вопрос и распределяет его между агентами. Офис-менеджер проводит утреннюю планёрку и ставит задачи на доску.
3. **3D model**. 1 этаж по плану эвакуации, 24 помещения, сотрудники, сценарии клиентов (анализ, прививка, 30 клиентов сразу).
4. **Dashboard**. Лаборатория, клиника, вакцинация, очередь, сотрудники, учёт времени, документы. **Цифры демонстрационные**, кроме прайса и чек-листа документов.
5. **Maktab**. Обучение по должности (5 дней), фразы на 3 языках, оплата Humo/Uzcard/QR, каталог анализов, тренажёр диалога с ИИ.
6. **Muammolar**. Сотрудник пишет, что мешает работе. Видит только руководитель.
7. **Skaner**. Фото документа → ИИ определяет папку и поля → запись в архив.

## Как устроена техническая часть

- Каждый раздел живёт в своём Shadow DOM, чтобы стили и id не пересекались. Код раздела получает `document`, подменённый на его ShadowRoot (`docFor()` в `hub.html`).
- Возможности Claude берутся через `window.claude.use(...)`:
  - `db` — общая база (документы ниже), `user` — кто открыл (владелец / сотрудник),
  - `sample` — запрос к Claude (агенты, сканер, тренажёр), `downloads` — скачивание CSV.
- Вне Claude `window.claude` нет: страница открывается, но база пустая, ИИ не отвечает, отметки не сохраняются. Это ожидаемо.
- Внешние библиотеки: three.js r128 (3D), SheetJS xlsx 0.18.5 (Excel для Аналитика), шрифты Google (Golos Text, Unbounded).

## Открытые вопросы и известные проблемы — нужна помощь команды

**Данные (нужен ответ от сотрудников):**
1. Прайс лабораторных анализов (название, цена, подготовка, срок готовности). Без него Малохат знает только вакцины.
2. Кабинет директора, должность Бакиева Жохонгира, фамилия Муножат.
3. Дни работы невролога Юсупова.
4. Где находятся помещения 25–27 (МСП)?
5. Утвердить обязанности и 5-дневные пособия (`data/guides.json`), особенно регистратуры, вакцинации и лаборатории.
6. План 2 этажа (фото или план эвакуации).
7. Пример дневной выгрузки из Sirocco в Excel, чтобы дашборд показывал реальные цифры.

**Технические ограничения (идеи решений приветствуются):**
1. Вход сотрудника: имя выбирается из списка, без пароля. Нужно связать аккаунт Claude с сотрудником (например, руководитель привязывает id аккаунта к имени в базе).
2. Агенты работают, только когда кто-то открыл приложение. Для автоматической планёрки в 8:00 нужен запланированный запуск или свой сервер.
3. Возможно, ИИ расходует лимит аккаунта того, кто им пользуется, а не подписку руководителя. Это нужно проверить на 2–3 сотрудниках.
4. Дашборд на демо-данных, пока нет связи с Sirocco (выгрузка Excel или API Sirocco, если он есть).
5. Malohat для клиентов в Telegram: нужен бот и платный API/сервер, пока не делали.
6. 3D-модель тяжёлая (≈320 КБ, фото внутри), на слабых телефонах может открываться медленно.
7. Внешний вид раздела в тёмной теме проверен не во всех разделах.

## Как помочь

- Неверные данные (комнаты, должности, обязанности, цены): пишите номер пункта и как правильно.
- Изменения кода: правьте `src/`, запускайте `python3 src/build.py`, проверяйте `app/index.html` в браузере. Публикацию в Claude делает руководитель.
- Ошибки: раздел, что сделали, что ожидали, что произошло, скриншот с телефона.
